# PWA behavior

Serwist precaches generated application assets and the `/~offline` route. Navigations are never runtime-cached because signed-in HTML can contain account details; offline navigation falls back to `/~offline`. Versioned scripts, styles, fonts, and workers use cache-first; public icons use stale-while-revalidate. `/api`, `/auth`, Supabase REST/RPC/Auth, and Realtime responses are excluded. Authenticated data stays in user-scoped IndexedDB rather than Cache Storage. The worker asks before activating a waiting update, registers a best-effort background sync wakeup, and the app requests persistent storage after workspace load.

The manifest declares a stable app identity, root scope, standalone display, app colors, PNG icons, and Today/Later shortcuts. Icons are generated from the original NestList vector; a 180px Apple touch icon is included. A shared install guide is available from the website header on every route (including login) and captures supported browser install prompts across navigation. After an installation event, the header button reads “Open app” and provides launch instructions. On iPhone/iPad it explains Safari → Share → Add to Home Screen → Open as Web App (if shown) → Add. Open the Home Screen icon before enabling push. The install header hides in standalone mode. A browser tab cannot force-launch an installed iOS web app; the guide directs users to the Home Screen. Settings provides a test popup independently of push subscription. Installability and offline navigation still need browser validation on desktop Safari/Chrome and Android Chrome.

While open, local data remains available offline and reminder actions use the local repository. Due task reminders show dismissible in-app popups even without notification permission; when permission is granted, they also request a system notification. The local scheduler continues through successive reminders and limits reminders to the current assignee (or creator if unassigned). Popups require the app to remain open; they are not an email or background delivery channel. Settings offers a daily popup summary independently of push subscription. Server Web Push uses the delivery ledger and VAPID Edge worker. The daily summary groups all open tasks scheduled for the user’s local date, sends one notification at the selected local time, and updates the app badge where supported. It does not use email. On iPhone and iPad the user must add the app to the Home Screen before enabling Web Push. A PWA cannot promise delivery when fully closed and offline.

Manual release checks: install in desktop Chrome/Safari and Android Chrome, add to iOS Home Screen, enable notifications separately on each device, use the Settings test notification (the in-app popup should appear even with browser permission denied), schedule two consecutive reminders and verify both popups, verify one closed-app push from the deployed Edge worker, reload each app offline, confirm a waiting-worker update prompt, inspect Cache Storage for authenticated responses, and run Lighthouse PWA/accessibility audits over HTTPS.
